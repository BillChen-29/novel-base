# 真实前文实验与连续性审计结果

2026-10-19。结论：母题资料可以细分，但当前目录混有多种知识作用；原有记忆功能部分有效，尚不足以可靠支持截点续写。把前文接入向量检索后，主要问题是缺少条件与阶段判断，而非缺少向量。

## 1. 根据实际资料拆分

对 10 份代表条目核对来源，得到 61 条记录：8 母题、24 情境、21 案例、3 世界规则、3 意象、2 手段。51 条原“情境原型”中只有 24 条建议视为情境。分类均为提案，153 条唯一引文的字符区间、行号和来源 SHA 已核验。

合理的数据关系是：共享母题描述可复现机制；情境描述某类人物、目标、阻碍和条件的组合；本书实例绑定具体角色、已发生阶段和前文证据。情境与母题允许多对多关联。案例、意象、规则和技巧各有用途，不宜强制二分。

例如，“一夜之功”中的限时完成情境可与“倒计时”关联；“故事救命”和“诬陷求生”共享某些案例。另一方面，“三界宇宙”的编号描述空间结构，不能作为场景先后；“故事救命”的内层故事不能当作外层主角下一场。详见 [分层说明](KNOWLEDGE-SPLIT.md)。

还发现库内适用范围冲突：“故事救命”收录教育案例，而排除条件强调诬陷；“预言难逃”包含改变未来的案例，却又排除成功阻止预言。原文限制应保留并审阅，不能直接批量生成硬规则。

## 2. 用了哪些真实前文

从 Downloads 的两本 TXT 中选取两个局部连续事件段，每段设两个截点。逐段审阅到封存后文末尾，排除梦境回忆、跨年日记、跨时电话及跨线回叙作为连续动作样本。背景说明和对往事的转述保留在源文，但不计为当下新发生事件。

| 小说 | 截点 | 前文字符 | 封存后文字符 | 离线观察到的实际承接 |
| --- | --- | ---: | ---: | --- |
| 全球高武，我却是旧日之主 | 监控发现五名来人 | 299 | 361 | 观察 → 准备应对 |
| 同上 | 已鸣枪、持枪对峙 | 1071 | 521 | 对峙 → 身份澄清 |
| 我的五脏六腑，皆为魔神 | 尸体交接、官员离开 | 625 | 307 | 交接 → 检查与推断 |
| 同上 | 初检并提出模仿犯案判断 | 1246 | 542 | 初检 → 职业建议与动机追问 |

总计 19 条带前文引文的状态标注。明确区分已发生、人物说法、观察、推断和未来安排。例如“新仵作明天来”没有被标为已到场；“可能是模仿犯案”没有被标为已经破案。

每个截点建立独立项目快照和索引，里面只有允许读取的前文。同书较晚截点的事实不能进入较早截点。原文按 UTF-8 解码、不归一化换行，保存字符半开区间和源文件 SHA。后文单独封存；离线后文审阅者未看检索排名，未修改冻结查询。正文及本地路径不进入本目录的可提交摘要。

## 3. 实际检索结果说明了什么

全库按来源结构提取 178 个原条目与 791 个情境／案例段候选，共 969 条；另外编码 8 条查询，共 977 个向量。使用本地 EmbeddingGemma 300M Q8_0，768 维，QMD 2.1.0 格式函数、node-llama-cpp 3.18.1、Metal。编码约 22.55 秒，只代表本机本批次。

两种查询分别是截点前最后 800 字符，以及只用前文标注的当前目标和状态。各做 BM25 和向量检索，再分别显示两类候选的前三条。查询长度不同，没有独立相关性金标；没有据排名调整本轮样本，也没有报告“准确率提升”。

| 实际现象 | 根据前文及源资料作出的分析 |
| --- | --- |
| 监控发现陌生人，状态向量的原条目首位是“倒计时” | 前文有紧张气氛，但尚无明确期限及超时后果；不能确认母题已成立。 |
| 同一查询召回“身份面具”“门槛守卫” | 不知道对方身份不等于对方在伪装；出现陌生人也不足以确认守卫、边界和考验关系。 |
| 验尸推断，状态向量首位是“包公断鬼案”，第二是“模仿巫术” | 前者要求真假身份与辨认机制，后者涉及模仿物和交感因果。验尸、模仿犯案与其词义或题材相近，却没有这些机制的前文证据。 |
| 尸体交接召回“彭祖不死”“旱魃”等 | 当前候选更接近死亡、尸体题材；尚未提供可直接使用的工作交接和检查情境。这提示覆盖问题，不能据四例断言全库都缺失。 |

以上是来源核对后的定性诊断，不是独立评分集。下一阶段需要允许“没有适用候选”，不能每次强制套入一个母题。新引入的期限、身份或道具可以成为后续计划，但必须明确作为新发展并说明发生过程，不能回写成前文事实。

实际作者后文还说明：紧张对峙可以转为交谈，验尸可以转为人物关系。合理性评价应检查状态变化和因果承接，不把升级冲突、继续调查或猜中作者写法设为唯一答案。

## 4. 原有三个机制是否有效

另用隔离的合成边界样本，真实调用现有函数和命令入口，检查主流程提示传递。共 20 项：**7 PASS / 13 FAIL / 0 ERROR**。缺口包括当前未实现的新场景要求，并非声称本轮引入了 13 个回归错误。

| 机制 | 已实测有效 | 关键缺口 |
| --- | --- | --- |
| 历史正文检索 | 正确匹配项目索引时隔离有效；主链显式 auto-build 可刷新正常修改和删除 | 无续写截点参数；误传别书索引不拒绝；独立 query 可读旧缓存；保留修改时间的内容变更可逃过刷新 |
| 图谱上下文 | event 按章节过滤；主链确实收集图谱文本 | 最新人物状态和未来伏笔未按截点回溯；无视角知情过滤；关系边和原文证据未保留到写作上下文 |
| 事实引用原型 | 不存在于场景的引文被拒绝；正确 known_by 可过滤他人秘密 | 引文存在不代表支持事实含义；错误知情标签未被原文语义核验 |
| 进入写作器 | 主链已有检索与图谱收集入口 | Beat 路径截取 query 前 200 字符、总目标前 400 字符，后置检索与图谱信息可能丢失；previous_ending 存储后未用于扩写提示 |

一个直接反例：把“左手受伤”的真引文配给“左手完好无伤”的假事实，引用校验仍接受。因此它目前提供引文存在性校验，不能作为事实正确性保证。

主链有 auto-build，因此“默认 query 不刷新”的结论主要针对独立查询入口，不能泛化为主链所有修改都不刷新。图谱 event 过滤通过也不能泛化为全图的历史状态安全。

在四个真实前文快照上，历史接口返回片段对标注原句的严格覆盖为 raw 6/19、state 9/19；这只是完整引文字符串覆盖诊断，并非语义召回率。每个快照只有一段正文，也不是长篇检索测试。19 条原文引文均被校验接受，四例注入的不存在引文均被拒绝。图谱来自实验种入的标注，只验证读取和输出，不验证自动抽取；推断和未来安排被显式写进描述，未假定现有图谱原生理解这些状态。

源位置：`scripts/plot_rag_retriever.py` 的 retrieve 和缓存；`scripts/story_graph_builder.py` 的 cmd_context；`scripts/narrative_prototype.py` 的 _validate_project；`scripts/novel_flow_executor.py` 的 _generate_beat_draft；`scripts/beat_sheet_generator.py` 的扩写提示构建。逐项状态和源码 SHA 见 [runtime-summary.json](runtime-summary.json)，完整实际输出在本地 `runtime-data/continuity-audit/runtime-audit.json`。

## 5. 下一轮开发顺序与验收

1. **先修前文边界和信息传递。** 统一 project_id、文稿版本、章内截点及 POV；检索拒绝异书索引，图谱按截点恢复人物状态与伏笔；缓存用内容变化失效；完整前文尾段、证据和约束应进入最终扩写提示。用本轮相关失败用例验收，不能只验“收集函数有返回”。
2. **再完成小批量可用情境。** 从已核对条目提炼进入条件、已完成阶段、可能变化、角色槽位和证据。条件用“满足／冲突／未知”，并保留待审与适用范围冲突。共享案例与本书事实分库存放。
3. **加入候选适配判断。** 同时回答“当前是否已进入某母题／哪个阶段”和“下一场可以引入什么机制”。向量只提出候选，随后核对前文证据、角色目标、节奏目标和变化成本；允许无匹配。变体用于实现候选，不能把变体包含的结局误当已发生阶段。
4. **最后做受控续写。** 冻结前文→状态与引文→候选条件判断→下一场计划→生成→事实、知情与顺序核对；只有接受的生成文本才更新项目记忆。新增模型生成时再评估质量。本轮没有调用生成模型。

对单条事实，至少区分来源位置、叙述位置、事件时间、叙事层级、视角知情、信息类型和版本。顺叙小样仍需这些边界；以后再扩展插叙、倒叙支持，不能把段落相邻直接当成事件先后。
