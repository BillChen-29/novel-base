# 续写前文边界修复（2026-10-24）

工作于 2026-10-24 开始，2026-10-25 完成复核。

本轮在原 novel-base 中修复“正文 → 历史检索／图谱 → 写作上下文 → Beat 扩写提示”的传递。优先保证写作入口拿到正确时点的材料；母题／情境分层仍采用上一轮的待审提案，尚未批量改写原始资料。

## 已实现的行为

| 环节 | 当前行为 |
| --- | --- |
| 作品隔离 | 索引绑定项目；误用另一作品索引、来源越界时拒绝。 |
| 前文截点 | 新章默认只读前一章及之前；可指定同章字符位置，位置之后的正文和派生摘要不进入检索结果。 |
| 直接承接 | 最近有效前文的末尾最多 2,000 字符独立进入提示，不依赖关键词是否命中。 |
| 引文定位 | 历史正文检索返回原始文件、起止字符、来源哈希，并按允许范围切取原文。图谱附带引文目前保留来源字段，未逐字重验其位置与哈希。 |
| 缓存 | 查询前检查正文内容变化与删除；保留修改时间的替换也会刷新。写作结果缓存包含前文、图谱、规划版本和视角；同一已完成操作可复用，前文变化会失效。 |
| 历史图谱 | 按章节／字符位置选取当时完整状态；不能从无版本的最新状态倒推旧状态。缺少时间依据的记录在有截点时省略并说明原因。 |
| 视角知情 | 指定角色后只接受明确标注该角色知情的图谱记录；事件参与者不自动等同于知情者。 |
| 写作入口 | 前文、检索证据、图谱和作者规划分别保留，实际扩写提示不再把完整约束裁成几百字。自定义提示不会重新加载无截点的项目记忆。 |
| 失败处理 | 检索／图谱失败时停止准备；Beat 扩写失败不复用旧扩写文件。拒绝会使产物路径覆盖正文的链接。 |
| 无模型模式 | 默认保存待写提示，不产出冒充模型生成的完成章节，不发布该草稿的故事记忆。旧固定文本演示须显式选择 `--draft-provider template`。 |

作者规划可以包含未来方向，它在提示中属于“计划”，不能视作已经发生的历史事实。上述截点保护约束的是历史正文、历史图谱及其派生检索内容。

## 验证结果

普通回归测试 268 项、旧写作流程 10 项、旧图谱函数 7 项均通过，代码审查与独立链接覆盖复验通过。

20 项能力审计在新接口下为 **18 PASS / 2 FAIL / 0 ERROR**，原来的 7 PASS / 13 FAIL 基线保留在 [runtime-summary.json](runtime-summary.json)。当前审计摘要见 [repair-runtime-summary.json](repair-runtime-summary.json)。新审计显式传入截点与视角，并给阳性人物样例标注有效章节；未放宽否定断言。

剩余两项失败：

1. 引文定位正确，但标注的事实与引文意思相反时，系统还不能识别。
2. `known_by` 已填入角色，但原文并不能证明角色知情时，系统还不能核实。

因此，目前能验证“引用了哪段允许读取的原文”，还不能自动保证“这段原文支持该判断”。已有状态和知情标注仍需审校。

真实小说截点复验为 **4/4 案例、68/68 项检查通过**。19 条既有标注事实中，18 条进入上下文；末例受最多 5 个事件的上限影响。两本下载原书与试验正文的字节散列均保持不变。明细见 [repair-prefix-summary.json](repair-prefix-summary.json)。使用上一轮两本本地小说的四个截点，两个相邻截点共享前缀；没有把它们视作四个独立样本。测试把前文与真实后文保留在同一文件中，经实际主入口准备扩写提示，并核对完整前文保留、后文段落抽查／未来标记排除、来源位置和正文不变。未调用生成模型，也未重新测试向量排序；结果说明上下文传递与截点过滤，不代表续写质量提升。

## 使用方式

继续新章仍使用 `continue-write`，默认历史截止于目标章的前一章。先查看一个现有章节内部截点的提示：

```bash
python3 scripts/novel_flow_executor.py continue-write \
  --project-root /path/to/story \
  --chapter-file '/path/to/story/03_manuscript/第1章 场景.md' \
  --cutoff-chapter 1 --cutoff-offset 600 \
  --pov-character character_id \
  --query '从当前动作继续，先验证已知线索' \
  --prepare-only --force-retrieval --no-research
```

返回 `prepared_context_file` 和 `prepared_prompt_file`，可查看完整上下文及实际第一段扩写提示。`--prepare-only` 不调用生成模型，不改动正文。同章截点目前只开放准备模式；尚未实现正文后缀替换、分支保存或同章自动接写。

`cutoff_offset` 为原始 UTF-8 文本解码后的字符位置，采用 `[0, offset)`；不是文件字节数。换行和 emoji 也计入位置。零表示该章尚无可读正文，负数、超长或无法唯一定位的章节会被拒绝。独立检索接口不指定截点仍支持全项目查询，主写作入口始终显式给出截点。

历史图谱支持 `source_position: {chapter, end}`、`known_by` 与完整 `state_history` 快照。旧记录没有时间／知情依据时不会自动补造，需先补标注；更新旧时点也不能沿用未来状态的其他字段。
