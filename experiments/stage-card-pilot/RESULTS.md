# 阶段卡与当前承接实验

2026-10-31。四张卡已经在 novel-base 中跑通“前文／基础状态 → 检索 → 条件审核 → 下一步提案”。本轮最有用的结果是：**历史上出现过某种结构，不再自动意味着现在还应继续它。**

## 连续前文推进后的结果

| 案例 | 截点状态 | 完整四卡池允许的下一步 | 实际检索表现 |
|---|---|---|---|
| case-01 | 拿到封口纸条，尚未读取 | 读取当前可访问的纸条 | 四条路线均取回 |
| case-02 | 已读到编号、理解用途，尚未输入 | 将已知内容用于开柜任务；不再次首次读取 | 四条路线均取回 |
| case-03 | 双方对钥匙、押金的处理仍有分歧，正在等回应 | 回应或追问既有诉求 | 原文关键词漏检，其他三条取回 |
| case-04 | 钥匙已交还，双方接受处理安排，一方离开 | 没有当前交涉提案；仍保留“曾发生对话冲突”的记录 | 即使取回对话卡，审核后也不输出继续争执 |
| case-05 | 账实不符，具体核对尚未开始，明确未决定追查到底 | 进行已明确的出库单核对 | 四条路线均取回；不判真相追寻触发成立 |
| case-06 | 一次检查完成但疑点未解，人物明确决定追查到底 | 沿已有疑点继续追查 | 四条路线均取回；不再次指定已经完成的那次核对 |
| case-07 | 新真实片段：人物讨论死因假说 | 没有本轮卡片所需的明确承诺或具体可执行核对步骤 | 相关卡可以排前，但不输出提案 |
| case-08 | 新真实片段：日常试饮交谈 | 未建立具体冲突、异常调查或载体读取关系 | 不因为有对话、有物件便放行相应卡 |

前三对是本轮原创的连续挑战案例，六个截点可以公开重放；后两例是本地小说中的新连续片段，与上一轮选段不重叠。原创案例的条件较明确，用于检查状态切换；这组结果不是自然分布的小说推荐准确率。

“继续追查”只是阶段级方向，具体新动作仍应由作者或下一步规划确定。本轮没有生成后续小说正文。

## 知识和运行设计的边界

| 卡片 | 本轮实际含义 |
|---|---|
| 对话情境 | 原文支持的具体关系冲突，加上本轮设计的“交涉仍进行、争议未解决”门槛 |
| 真相追寻触发 | 保留原资料的“发现疑点＋决定追查到底”，只确认触发阶段 |
| 信息载体流程 | 从传递—理解过程得到启发的新增通用流程；不计作织物传书母题命中 |
| 线索核对 | 从逐步探查未知得到启发的新增局部操作；不声称原资料已有完整假说核验算法 |

卡片、来源和查询描述在新案例生成及排名之前冻结，没有根据结果调整。原始知识文档未被改写。具体格式见 [FORMAT-v0.2.md](FORMAT-v0.2.md)。

## 暴露出的两个实际问题

**“当前焦点”还不能替代具体动作绑定。** case-06 已完成出库单核对，但整个缺货调查仍在推进。初始审核把“尚有具体核对待做”及“内容使用任务待完成”判成矛盾，实际上是自行将它们限定为已经结束的那次检查。输入只有“缺货查验”这一焦点，未提供唯一的动作／任务编号。

在编码和排名前，复核将这两项改为证据不足，保留初始判断与[裁定记录](adjudication.json)。当前卡因此不会放行动作指向不明的核对提案，但这不等于系统已经知道所有检查都完成了。下一步需要把载体、具体任务、动作实例分别绑定，再区分“继续未完步骤”“提出新的检查”和“重复旧动作”。本轮没有回头修改冻结卡片来消除这个失败。

**基础事实也需要拆开。** case-01 的一条整理事实混合了“收到纸条”和“纸条实际写有编号”。后者在未拆封时只有别人告知的依据，因此该复合事实被保留为报告层级，没有进入状态查询。下一版应分别保存交付事件、对方的说明和之后读到的内容。自动整理基础状态仍未实现。

## 如何运行与核验

复用已有 `prepare_candidates`、`semantic_review` 和 `match_motifs`；新适配器负责四卡统一准备、查询构建、检索和结果过滤。无界面依赖，也没有接入额外模型接口。基础事实、人物及焦点由本轮整理，154 条命题和对应人物知情由两名当前 AI 分组独立审核，审核员不看排名或配对另一截点；不存在人类金标准。

最终 154 条命题判定为支持 67、矛盾 6、证据不足 81。其中一个支持命题属于报告层级，未被升级为确定世界事实。程序核对来源及精确引文，但引文有效不等于语义判断必然正确。

本地模型仍为 EmbeddingGemma 300M Q8_0，768 维，经已安装的 QMD 格式函数和 node-llama-cpp 编码：四卡＋八段原文＋八条状态查询，共 20 个输入。公开六例另行编码 16 个输入，重跑后的逐例匿名结果与完整实验中的对应六例完全一致。

最终 **441 / 441 项 Python 测试通过**，含本轮新增 14 项。代码和安全复核通过；发现并修复了输出目录通过符号链接指向仓库外时的绕过问题。271 份原始资料和两本小说散列未变；真实正文、查询和向量只保存在本地忽略目录，正式故事记忆没有写入，未提交或推送 Git。
