# 阶段与当前承接条件：小样格式 v0.2

本轮在已有 v0.1 目录格式上增加少量标注与检索适配，不迁移全库，也不更改原有核验器。`motifs` 集合键继续兼容旧接口，每条的 `knowledge_kind` 决定它是母题、情境还是技巧。

| 层次 | 保存什么 | 本轮实现 |
|---|---|---|
| 原始资料 | 定义、阶段、案例、限制 | 原 `assets/` 文本与 SHA-256；只读 |
| 阶段／情境卡 | 槽位、独立条件、阶段、提案门槛 | `catalog.json`，四张卡 |
| 本项目基础状态 | 当前前文、人物已知事实、实际焦点 | 独立项目及截点；基础事实经 AI 审阅 |
| 派生审核 | 把卡条件填入本项目后，检查支持／矛盾／未知 | 旧 `prepare_candidates`、`semantic_review` |
| 当前推荐 | 实际检索候选与允许提案的交集 | 新实验适配器；提案不写回历史 |

## 一张卡需要表达什么

`source.path / sha256 / evidence` 保存原资料与精确引文；`basis` 和 `operationalization_note` 说明哪些是原文结构、哪些是本轮设计。引用原文不代表新增条件都由原文直接提出。

`roles` 在本轮统一为视角人物 `actor` 和具体事件焦点 `focus`。焦点用于约束条件指的是哪件事，仍由本轮整理；自动识别焦点和多事件绑定尚待验证。

`conditions` 将能独立变化的命题拆开。例如：持有载体、尚未读取、已经理解、知道用途、任务待完成分别审阅。所有条件都是待审核问题，卡片或变量名不能证明它成立。

`stages[].requires` 描述结构或阶段依据；`variants[].requires` 额外检查此刻是否可以推进。例如，过去的对话冲突可以成立，但下一步交涉还需要对方此刻可回应、分歧仍开放。未审、未提及、无法确认均保持未知。

本轮 `stage_mode` 使用 `alternatives`：列表顺序不代表时间。未读和已理解两个入口由当前证据区分；卡片不靠“后面的条件缺失”来猜测人物还停在前一阶段。对于需要严格事件次序的母题链，继续使用旧接口的事件锚点与顺序审核，不能用这组当前状态卡替代全部时间推理。

`retrieval_text` 是本轮编辑的简短检索描述。它与卡片标题一起编码；不把完整文档与压缩卡片的效果混为一个实验。本轮只比较同一组卡上的原文查询和基础事实查询。

## 四张卡的来源资格

| 卡 | 结构依据 | 当前推进门槛 | 结果可以怎样称呼 |
|---|---|---|---|
| 对话情境 | 具体立场、信息或情感冲突 | 当前仍可交涉且争议未解决 | 情境承接 |
| 真相追寻触发 | 发现疑点，明确决定追查到底 | 疑点仍开放、追查仍进行 | 母题触发阶段，不是全母题完成 |
| 载体读取／使用 | 由传递—理解过程启发的新流程 | 可访问且未读，或已理解且任务待做 | 通用信息流程，不是织物传书命中 |
| 线索核对 | 由逐步探查未知启发的新操作 | 问题未解、具体检查可做且尚未完成 | 局部技巧，不是完整悬念阶梯 |

“已完成”判断依赖具体事件与对象。例如，查完一张单据不表示所有调查都完成；开始另一项有依据的检查也不等于重复原动作。目前以焦点和审核命题表达这个区别，尚无独立的动作实例编号系统。

## 检索和审核如何衔接

1. 允许前文在进入适配器之前已经截断，每例只接受一个局部连续场景。
2. 当前 AI 审核基础事实与各卡条件，人物知情单独判断，只有支持且确定的命题可用。
3. 原文查询保留完整前文；状态查询只取原始基础事实中当前视角可用的文本，排除所有由卡生成的问题。若没有可用基础事实，状态路线返回空候选。
4. BM25 和本地向量各取前二名；分数只影响排序，不代替语义审核。
5. 实际写作输入只包含已取回且被允许的提案，以及相关的已审事实。全池审核结果另存，供分析漏检；不能补入实际推荐。

基础事实、焦点和审核仍由当前 AI／本轮整理后导入。已有软件能够执行这条流程，不表示这些语义工作已经自动化。
