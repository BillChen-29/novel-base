# 信息、情境与母题承接小样

2026-10-26。先看 [实际结果](RESULTS.md)。本轮在原有事实与知情审核后，增加两个有资料来源的母题条件匹配器；用原创顺叙片段检查内容、载体、获取过程与逐角色知情如何改变后续提案。不调用额外模型接口。

## 先区分信息与信息场景

| 层次 | 例子 | 在本原型中的作用 |
| --- | --- | --- |
| 内容命题 | 暗号是“松果” | 单独审核是否被前文支持 |
| 载体命题 | 这封信写着暗号“松果” | 单独审核；不能从知道暗号推导出来 |
| 来源命题 | 这封信由甲寄出 | 与载体不同，也不能从看到信推导出来；本轮尚未单独建寄件者样例 |
| 获取／传播事件 | 阿岚读信；阿岚转告；阿弥听清并复述 | 说明信息如何流动，为知情变化提供证据 |
| 角色知情关系 | 阿弥知道内容，但对载体的知情证据不足 | 对每个命题、每个角色分别审核 |
| 情境 | 掌握内容，而来源知情尚无支持 | 多个命题、事件、角色状态组成的局部处境 |
| 母题及变体 | 受阻表达经物质媒介传达；找解读者或用已有对照资料 | 依据具体条件和阶段选择待写方案 |

因此，“知道暗号写在信上”仍然是一个知情关系，其对象是载体命题；“读信得知暗号”才是获取事件。知道信息、相信信息和信息为真也有区别，本轮只允许“前文支持的确定命题＋支持的角色知情”进入写作依据；尚未实现错误信念的完整模型。

## 数据怎样连接

`fixtures.json` 保存项目独立的场景、候选事实和注释。`motif_annotations.atoms` 用 `fact_id` 标记内容、载体、获取事件、传播事件或状态；分类为本轮标注，不是自动抽取结果。母题实例另绑定角色、物件与条件。

`catalog.json` 保存两个条目的原文件路径、哈希、精确引文，以及本轮设计的条件、阶段和变体。原始资产未改写。条件模板填入角色后，必须与绑定候选的完整文本一致。例如“收到绣布”不能被重新命名为“理解绣布”。独立 AI 实际审核的正是这些实例命题。程序验证绑定与执行规则，不自行解释自由文本。

全项目哈希包含注释及资料目录摘要；审核还绑定当前允许前文与截点。事实审核、条件目录或前文发生变更时不能沿用不匹配的结果。同名角色或事实编号不跨项目共享记忆。

## 判断和写作输入

- 世界命题有支持且为确定事实：`true`；确定命题有明确反证：`false`；缺审、转述、推断或证据不足：`unknown`。
- 知情关系单独保留三态。未列入已知集合不等于角色肯定不知道。
- 必要条件全真时通过，有反证时阻止，其余待补证据。母题未到结局不妨碍早期阶段成立。
- 本轮只对明确选出的事件链检查时间次序。审核者须在允许前文中标出 `event_anchor`，确认该片段描写事件实际发生，并提交与整个截点对应的 `chronology_review`。不拿事实原引文的位置自动充当时间。
- 缺事件锚点、缺顺叙审核或锚点重叠时，次序保留未知；明确逆序时阻止相应阶段。存在倒叙、插叙或内层故事时，需另行判断，当前程序不会自动识别它们。
- 作者核对视图与视角写作包分别计算。隐藏事实不会决定视角提案，也不会出现在其标题、理由或输入事实中。
- 如果角色已知后续事件发生，却只因次序尚未确认而无法确认阶段，暂停该母题提案，避免回退后重复建议已经做过的动作。

`writer_packet` 只含可用事实和标为创作提案的后续方案。`writer_prompt` 直接序列化该包。全局审核、未通过候选与原始母题结局不混入写作依据；提案不回写故事记忆。

## 运行

在仓库根目录运行：

```bash
python3 experiments/motif-applicability/run_experiment.py \
  --run-date 2026-10-26 \
  --output runtime-data/motif-applicability/demo/results.json \
  --html runtime-data/motif-applicability/demo/report.html
```

这会重放已保存的实际 AI 判断，不会重新调用 AI。九个截点均为原创，不需要下载小说。JSON 可审计每条命题、每个阶段和写作包；HTML 可以展开前文和写作输入。输出不能覆盖输入或仓库资产。

单项目接口：`scripts/motif_matcher.py`，参数为 `--project --packet --review --catalog --repo-root`，默认向标准输出写 JSON。Python 接口为 `match_motifs(project, packet, review, catalog, repo_root)`。沿用 `semantic_review.prepare_review` 冻结截点、`apply_review` 验证事实；没有改变原有四张策略卡或默认写作主流程。

验证：

```bash
python3 -m unittest scripts.tests.test_motif_matcher scripts.tests.test_motif_experiment -q
```

## 当前范围

两个条目为“织物传书”和“禁忌之禁”。阶段是针对这两项资料的操作化方案；“找解读者”和“用对照表”是本轮依据解码机制设计的承接变体，不是声称原文已给出的分类。资料中的文学案例归属未经本轮外部核实。

尚未完成全库规范化、自由文本自动抽取、自动召回所有母题、错误信念建模或正文生成。九个截点只能验证这些设计能否执行，不能据此宣称语义准确率或续写质量。下一次扩展应保留正例、明确反例、证据不足以及相邻截点对照，并继续检验真实顺叙片段。
